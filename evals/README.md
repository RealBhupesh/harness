# Relay evaluations

`pnpm eval` runs four isolated Git repositories: add a function while retaining an existing export, fix a failing addition test (the mock deliberately requires a second attempt), refactor a sum implementation without changing behavior, and a synthetic long-context task with repeated document reads before implementation. Each uses actual tool writes, test commands, independent verification and Git integration. A scoring oracle outside the worker checkout checks additional cases after integration. A separate negative guard claims success while leaving broken code and must be rejected.

The scorecard reports success rate, mean attempts per benchmark, false positives among approved tasks, estimated mean cost per benchmark, elapsed milliseconds and original/sent message bytes. `contextSaved` compares the full retained dialogue/evidence with the transmitted projection for the same calls. `estimatedMessageTokens` is sent message bytes divided by four, rounded up; this excludes tool definitions and provider envelopes and is not provider token usage. No approvals produce `null` for the false-positive rate. The negative guard is reported separately and always uses MockProvider. A mock regression or approved negative guard makes the command fail. Fixtures are removed after scoring; failure notes are included in output.

The deterministic mock run validates orchestration, not general model capability. Its expected baseline is 4/4 successes, 1.25 attempts/task, 0 observed false positives, and $0 simulated cost. The synthetic long-context fixture measured 89.1% fewer message bytes with compaction enabled. Mock usage is scripted; this is not an actual API token or billing reduction. Four examples do not establish production reliability. For an offline comparison with compaction disabled, import `scorecard` from `evals/run.ts` and pass `ConfigSchema.parse({context:{enabled:false}})`.

For optional live benchmarking, provide an API key through the environment and a non-secret JSON `RELAY_EVAL_CONFIG` containing `provider`, role `models`, correct per-million `prices`, and budget caps, then run `pnpm eval --live`. Config uses the same schema as `.relay/config.json`. Caps apply separately to each fixture; total possible spend is up to four fixture budgets. Real calls are opt-in, incur costs, and have not been tested in this environment. The live model chooses its own reads, so the long-context fixture does not guarantee the repeated mock sequence. Live failures remain measurements rather than being replaced with mock success.
